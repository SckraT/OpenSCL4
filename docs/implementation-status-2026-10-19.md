# OpenSCL4: реализация и проверки на 2026-10-19

Последние изменения и проверки описаны в заключительном разделе; предыдущие разделы сохраняют результаты более ранних этапов.

Работа выполнена в `.claude/worktrees/soundcore-android-pixel-build-a973c9`, ветка `desktop-slint`, поверх `9db132ee`. Изменения пока не закоммичены и не опубликованы. Незакоммиченная переделка egui в основном checkout сохранена отдельно. [Согласованный план](cross-platform-release-plan.md) подтверждён пользователем; повторного интервью не требуется.

## Реализовано

- Пять групп правил перенесены из Slint-клиента в `lib/src/client`: доступность и группировка настроек, шкалы звуковых режимов, заряд, эквалайзер, состояние пресетов. Desktop использует их напрямую, Android — через типизированные UniFFI-адаптеры. Rust и Kotlin проверяют общие примеры из `lib/tests/fixtures/client_rules.json`. Устройство остаётся источником действующих настроек.
- Новая идентичность OpenSCL4: Android application ID, Windows AppUserModelID и установщик, Linux desktop ID и пакет, отдельный каталог данных и изолированный механизм одного экземпляра Windows. Linux пока сохраняет прежнее отсутствие ограничения числа экземпляров; эту часть системной интеграции нужно довести и проверить отдельно. Автоматического переноса данных OpenSCQ30 нет. Сохранены исправления трея, иконки и выпадающих списков.
- Подготовлен контроль доступности Linux-трея: скрытие разрешается после регистрации нашего элемента у доступного хоста, потеря трея возвращает окно. Без трея закрытие завершает приложение. Проверка поведения на Linux ещё нужна.
- Общий `scripts/release.py` собирает Windows, Linux и четыре Android ABI, записывает происхождение пакетов и хеши. Проверка комплекта требует одной версии/ревизии, полного набора пакетов, совпадающей Android-подписи; stable дополнительно требует запись физической Linux-проверки. Публикация ручная.
- Подготовлены `.deb`/`.tar.gz`, Windows-установщик, CI всех платформ, установка/удаление Linux-пакета и запуск X11/Wayland в CI. Сборки фиксируют инструменты и lock-файлы. Сценарий UniFFI теперь отслеживает саму native-библиотеку и конфигурацию, чтобы не оставлять старые привязки.
- Создан новый постоянный Android-ключ и резервный архив с ограниченным доступом. Они игнорируются Git. Архив пока находится на том же диске, внутри рабочего checkout; перед публикацией или удалением checkout его нужно скопировать в отдельное защищённое хранилище. Значения ключей и паролей в отчёте не приводятся.

Удалена неиспользуемая build-зависимость UniFFI у native Android crate: выбранный граф native-сборки уменьшился со 191 до 174 уникальных package/version, из него исчез `uniffi_bindgen`. Сам инструмент генерации привязок по-прежнему нужен отдельно. Это сокращение графа native-сборки, а не доказанное сокращение всего pipeline на 17 зависимостей или определённое число секунд.

## Что ещё необходимо до стабильного выпуска

1. Собрать подписанные APK всех четырёх ABI; проверить установку новой линии рядом со старой и последующее обновление с сохранением собственных данных.
2. Собрать Windows-установщик закреплённым Inno Setup и проверить отдельную установку/обновление.
3. Запустить подготовленный CI и Linux package checks; выполнить согласованную матрицу GNOME/KDE, X11/Wayland, потерю/возврат трея и физические проверки Liberty 4 Pro. Linux остаётся preview до завершения этих проверок.
4. Перенести резервную копию Android-ключа на отдельное защищённое хранение и настроить приватные CI secrets.
5. Зафиксировать исходники, назначить версию и общий тег; собрать комплект из одной ревизии, проверить его по [руководству](build-release.md) и вручную опубликовать.

Запуск Docker Desktop для Linux-проверок не состоялся: автоматическая проверка разрешения вернула ошибку исчерпанной квоты, а не заключение о небезопасности команды. Обход разрешения не выполнялся. На предыдущем этапе обычные попытки Gradle ограничивались доступом Java к пользовательскому кэшу/daemon и writable-проверками sandbox. На заключительном этапе разрешённый локальный прогон с пользовательским кэшем и SDK состоялся; его результаты приведены ниже. Linux-проверки этим не подтверждены. macOS остаётся следующим этапом.

## Продолжение унификации: значения эквалайзера и быстрые переключатели

Android больше не содержит собственного разбора и форматирования значений эквалайзера через BigDecimal. Ввод, точность, диапазон и представление частоты используют существующие функции Rust через четыре добавленных UniFFI API. Форматирование единиц Гц/кГц остаётся локализованным в Android. Теперь оба клиента принимают десятичную запятую и знак минус U+2212, отвергают лишнюю ненулевую точность, переполнение и экспоненциальную запись. Последнее раньше отличалось: BigDecimal на Android принимал экспоненты, desktop их отвергал.

Выбор быстрых переключателей перенесён из `desktop/src/model/quick_toggles.rs` в `lib/src/client/quick_toggles.rs`. Desktop использует его через прежний импорт, Android — через тонкий адаптер `QuickToggles.kt`. Общая реализация сохраняет порядок, убирает дубли и недоступные настройки, выбирает LDAC только при отсутствии сохранённого выбора. Явно пустой выбор остаётся пустым. Форматы хранения платформ не менялись.

Добавлены 42 общих примера: 21 случай ввода, 8 форматирования, 7 частот и 6 наборов быстрых переключателей. Они проверяются в Rust и новом Android `ClientValuesContractTest`. Два существующих теста быстрых переключателей переехали вместе с реализацией из desktop в core, поэтому текущие числа тестов — 290 core и 34 desktop. Эти тесты, интеграционные проверки, doctest и Clippy с `-D warnings` прошли.

Для локальной проверки границы UniFFI собрана свежая host-библиотека, из неё сгенерированы новые Kotlin-привязки. Kotlin 2.4.21 скомпилировал привязки, новые адаптеры и тесты; четыре JVM-теста (`ClientValuesContractTest` и `SoundEqualizerValuesTest`) прошли с загрузкой свежей DLL через JNA. Использованы существующие скомпилированные классы неизменённых Kotlin-обёрток и локальный JBR 25; результат не заменяет полный Gradle-прогон, Android ABI-сборку или UI-проверку. Локальный вспомогательный runner и лог находятся в игнорируемом `target/unification-validation/`. Обычный CI запускает новые тесты через существующий Gradle task.

Windows release EXE, описанный выше, собран до этого продолжения; его поведение быстрых переключателей сохранено, но текущие изменения исходников ещё не включены в новый релизный комплект. Публикация не выполнялась.


## Углубление общих модулей: перенос эквалайзера и применение пресета

Формат переноса профилей эквалайзера, преобразование дБ в единицы устройства и проверка числа полос/диапазона объединены в `lib/src/api/equalizer_profiles.rs`. Предпросмотр обоих клиентов и доверенный обработчик импорта используют одну проверку. Обработчик по-прежнему проверяет весь набор до записи в хранилище, возвращает подробную ошибку с именем профиля и номером полосы. Формат JSON, точное сравнение имён, округление и поддержка моделей с нулевой дробной точностью сохранены. Общие граничные примеры теперь сравнивают предпросмотр с фактически сохранёнными значениями, а не только с другой функцией предпросмотра.

По подтверждённому решению пользователя последний применённый быстрый пресет относится только к текущему подключению. `QuickPresetActivation` в ядре последовательно выполняет запросы разных обработчиков и записывает имя только после успешного завершения применения, включая повторную запись связанных настроек. Ошибка сохраняет предыдущую успешную отметку. После отключения отметка недоступна; новое подключение начинает без неё. Сами сохранённые пресеты и их поля не удаляются. Совпадение текущих настроек по-прежнему проверяется отдельно, по значениям устройства.

Android хранит этот объект в native-обёртке устройства. Временный обработчик уведомления и обработчик окна используют один объект; обновление передаётся через существующий callback изменений и `DeviceConnectionManager`. Экран больше не присваивает имя сразу после нажатия. Desktop получает имя в snapshot текущего подключения; прежнее поле `lastPreset` больше не читается и не записывается в конфигурацию. Старое поле игнорируется при чтении прежнего файла настроек, остальные настройки сохраняются.

Добавлены управляемые асинхронные проверки успешной записи, ошибки чтения пресета, ошибки повторной записи, последовательности параллельных запросов, отключения во время запроса и нового подключения. Интеграционные проверки проходят через desktop controller и Rust → UniFFI → Android `DeviceConnectionManager`, включая разные обработчики и сохранность пресетов после переподключения. Эти проверки обнаружили панику демо-подключения при повторной подписке на статус: демо возвращало receiver только один раз, хотя настоящие backends допускают независимых подписчиков. Демо исправлено; native-наблюдатель Android также сохраняет одну подписку между ожиданиями, а объект применения пресета читает сохранённую подписку вместо создания новой при каждом запросе.

Проверка этого этапа после исправления демо: 296 тестов core, 35 desktop-тестов, две интеграционные проверки и один doctest прошли; два doctest штатно пропущены. Форматирование и проверка пробелов также прошли. Обычный Clippy core/desktop/Android с `-D warnings` прошёл. Полный `:app:testX86_64DebugUnitTest` через Gradle прошёл: 117 JVM-тестов, без пропусков и ошибок, включая свежие host DLL, Android x86_64 native-библиотеку и сгенерированные привязки. Использован установленный JBR 25.0.3 и закреплённые SDK/NDK; релизный CI с JDK 21 этим не проверен. Предупреждения старых Android API, формата строк, JNA/ByteBuddy и Gradle deprecations остаются предупреждениями. Это не сборка подписанного APK и не запуск на устройстве.

В Gradle добавлена native host-библиотека во входные файлы JVM-тестов: изменение только Rust больше не должно оставлять старый успешный результат тестов при неизменных Kotlin-привязках.

Это изменения исходников и проверок. Прежний release EXE и релизный комплект не содержат этот этап до новой сборки. Физические Bluetooth-проверки, UI-проверка на Android и согласованная Linux-матрица остаются отдельными проверками перед выпуском.


## Единое чтение настроек устройства

После выбора пользователем первого кандидата архитектурного обзора реализовано общее групповое чтение. `SoundcoreDeviceTemplate.settings_by_category` копирует device state один раз и получает все настройки из этой копии. Watch borrow отпускается до вызова обработчиков. Порядок категорий и настроек, пустые категории, пропуск недоступных настроек и прежняя семантика повторных id сохранены. Desktop уже вызывал этот метод и автоматически использует новый путь. Development-устройство с неизменяемым состоянием сохраняет прежнюю реализацию по умолчанию. Отдельное хранилище профилей эквалайзера не становится частью общей транзакции снимка.

В UniFFI добавлен один вызов `settingsByCategory`, возвращающий упорядоченный список категорий и их настроек. Сами значения `Setting` используют прежнее JSON-преобразование. Android `DeviceSettingsManager` публикует один shared `StateFlow` для своих подписчиков: чтение выполняется в `Dispatchers.Default`, начинается при появлении подписчиков и останавливается при их отсутствии. `null` означает загрузку, пустой список — завершённое чтение без настроек. Закрытие manager отменяет producer; другое подключение получает собственный manager и начальное состояние. Проверка выявила, что возврат синхронного native-вызова может обойти ожидание отмены при объединении операторов Flow: перед публикацией добавлена явная проверка `ensureActive`, поэтому завершившееся после отмены чтение отбрасывается.

Экран теперь подписан на один результат и выводит из него категории, настройки по категориям и общий список. Прежние независимые `categoryIdsFlow` и `getSettingsInCategoryFlow` удалены. `allSettingsFlow` для остальных существующих потребителей выводится из того же результата с устранением повторных id. Уведомление, виджет и отдельное наблюдение LDAC в фоновом модуле сохраняют свои текущие способы чтения; их lifecycle этим этапом не переносился.

Добавлена проверка настоящего Rust seam с подсчётом копий и параллельной заменой состояния во время выполнения обработчиков. Она подтверждает одну копию и значения одного захваченного device state. Android-проверки проверяют отзывчивость UI-потока, два одновременных подписчика с одним native-чтением на обработанный сигнал, отсутствие старых поэлементных вызовов и отбрасывание позднего результата закрытого подключения. Настоящая demo native-проверка сравнивает новый результат UniFFI с прежним чтением категорий и отдельных настроек.

Общий Rust-прогон прошёл: 297 тестов core, 35 desktop, две интеграционные проверки и один doctest; два doctest штатно пропущены. Форматирование и проверка пробелов прошли. Clippy core/desktop/Android с `-D warnings` прошёл. Полный `:app:testX86_64DebugUnitTest` прошёл: 119 JVM-тестов без ошибок и пропусков со свежими host DLL, Android x86_64 native-библиотекой и UniFFI-привязками. Локальный JBR 25.0.3; релизный JDK 21, другие ABI и физическое устройство этим прогоном не проверены. Сокращение вызовов и копий проверяется тестами; выигрыш времени запуска, CPU и памяти на физическом устройстве пока не измерен. Новый release-комплект не собирался.
