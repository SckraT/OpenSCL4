# Материалы SoundcoreNext для миграции OpenSCL4

Проверены SoundcoreNext `v2.0.0` (`c1bf3e6881d2806972bf1fbe7f52fd5589997462`) и OpenSCL4 `d26c4031df39729e32df744ac74af450d2d4b247`. Пути SoundcoreNext ниже относятся к этой ревизии. [Исходная ревизия OpenSCL4](https://github.com/SckraT/OpenSCL4/commit/d26c4031df39729e32df744ac74af450d2d4b247)

## Корпус и опорные модели

В `core/data/conformance.json` 503 уникальных кадра, 36 меток, 26 пар команд и 8 групп. Источники по метаданным — 500 кадров из приложения и 3 из A3062. Все кадры исходящие. Проверка объявленной длины и контрольной суммы прошла для всех 503 записей. Кадры хранятся как hex-строки с полями `label`, `source` и `frame_hex`. Проверка воспроизводится на указанной ревизии. Корпус предназначен для фрейминга. Для паритета возможностей нужны ответы устройств и проверка результатов записи по моделям. Источники — `core/data/conformance.json`, `core/crates/protocol/src/lib.rs` и `core/crates/protocol/tests/conformance.rs`.

Измеренные фикстуры хранятся отдельно от корпуса.

| Модель | Фикстуры в `core/data/` | Что они позволяют проверять |
| --- | --- | --- |
| A3062 | `a3062-state.json`, `a3062-sound-modes.json`, `a3062-eq-presets.json`, `a3062-eq-custom.json`, `a3062-dual-connections.json` | Состояние, режимы звука, эквалайзер и сценарии dual connections |
| A3949 | `a3949-state.json` | Чтение состояния. Для проверки записи потребуются другие фикстуры |
| A3954 | `a3954-state.json`, `a3954-sound-modes.json`, `a3954-eq-presets.json` | Состояние наушников и кейса, запись режимов звука и тела команд профилей эквалайзера |

Связь между JSON и ожидаемым поведением видна в `core/crates/models/tests/`. Все три модели входят в каталог текущего OpenSCL4 из 40 кодов моделей. При переносе нужно сверять эти примеры с действующими реализациями из `lib/src/devices/soundcore/`. [Каталог OpenSCL4](https://github.com/SckraT/OpenSCL4/blob/d26c4031df39729e32df744ac74af450d2d4b247/README.md#supported-devices)

## Desktop и локализация

`desktop/ui/SOURCE.md` относит Slint-дерево к OpenSCL4 `01276e08` и перечисляет изменения форка. Сопоставлять стоит изменения компонентов в `desktop/ui/components/` и темы `desktop/ui/theme.slint` с текущими файлами OpenSCL4. Отдельные кандидаты — каталог динамических строк `desktop/src/messages.rs` и инструменты Windows UIA в `tools/ui-capture/` с изолированным деморежимом. UIA использует имя двоичного файла и русские подписи форка. Его запуск на новом клиенте потребует адаптации. [Текущие компоненты OpenSCL4](https://github.com/SckraT/OpenSCL4/tree/d26c4031df39729e32df744ac74af450d2d4b247/desktop/ui)

В обеих версиях одинаковый набор из 15 PO-локалей, а английский служит исходным языком. SoundcoreNext проверяет полноту русского каталога и покрытие строк из `messages.rs`. Текущий OpenSCL4 уже проверяет плейсхолдеры в `desktop/tests/translations.rs`. При переносе динамических строк следует сохранить эту проверку. [Проверки переводов OpenSCL4](https://github.com/SckraT/OpenSCL4/blob/d26c4031df39729e32df744ac74af450d2d4b247/desktop/tests/translations.rs)

## Происхождение и приватность

Манифесты обоих проектов указывают GPL-3.0-or-later. Для переносимых файлов сохраняются уведомления об авторстве и происхождении из `NOTICE` и `desktop/ui/SOURCE.md`, а для шрифта Onest — его лицензия из `desktop/ui/fonts/OFL-Onest.txt`. Перед импортом JSON требуется проверить маскирование идентификаторов по семействам и полям, включая тело кадра, а затем повторно проверить длину и контрольную сумму. Исходный тест корпуса печатает hex кадра при ошибке разбора. В публичном CI для такого сбоя достаточно метки строки и ошибки парсера. Проверка фрейминга сама по себе маскирование не подтверждает. [Руководство OpenSCL4 по историческим материалам](https://github.com/SckraT/OpenSCL4/blob/d26c4031df39729e32df744ac74af450d2d4b247/docs/history/upstream.md)
